# HA/TCP WAN Accelerator 작업 일지

작업 기간: 2026.07.01 ~ 2026.07.30

## 1. 작업 목표

기존 HA/TCP 논문의 WAN Accelerator 구조를 분석하고, wan_acc 애플리케이션을 F-Stack 기반으로 실행할 수 있도록 수정하는 것을 목표로 했다.

기존 wan_acc는 Linux socket API 기반으로 동작했기 때문에 실제 통신이 Linux TCP stack을 통해 처리되었다. 이를 F-Stack API 기반으로 변경하여 DPDK/F-Stack 환경에서 WAN 구간 통신이 수행되도록 수정했다.

## 2. 전체 진행 흐름

HA/TCP 원본 코드 분석  
→ FreeBSD/HA-TCP 코드 전체 덮어쓰기 시도  
→ FreeBSD 버전 차이 및 F-Stack 의존성 문제로 빌드 실패  
→ F-Stack 원본 구조 복구  
→ HA/TCP 핵심 migration 코드만 선별 이식  
→ SOMIGRATION / SMCP / TCP migration 관련 코드 추가  
→ HA/TCP 기능이 포함된 F-Stack 라이브러리 빌드  
→ wan_acc를 Linux socket API에서 F-Stack API로 변경  
→ MS와 ES의 WAN 연결 구조 수정  
→ Front Worker / Back Worker 역할 구분  
→ wrkwrk를 이용한 성능 측정  
→ perf 및 FlameGraph를 이용한 병목 분석

## 3. 주요 코드 수정

### F-Stack API 전환

WAN 구간에서 사용하던 Linux socket API를 F-Stack API로 변경했다.

- socket() → ff_socket()
- bind() → ff_bind()
- listen() → ff_listen()
- accept() → ff_accept()
- connect() → ff_connect()
- epoll → ff_epoll

### MS-to-ES WAN 연결 처리

MS가 ES로 WAN 연결을 생성하는 과정에서 비동기 connect 문제가 발생했다. 이를 해결하기 위해 WAN_CONNECTING 상태 처리, EPOLLOUT 우선 처리, finish_wan_connect(), find_wan_stream_by_fd() 등을 추가했다.

### ES WAN listener 등록

ES 측에서는 WAN 연결을 받아야 하므로 listener fd를 F-Stack epoll에 등록하도록 수정했다.

## 4. Front Worker와 Back Worker 역할

Front Worker는 데이터 수신, 버퍼링, chunk 분할, 중복 chunk 검색, 신규 chunk와 reference chunk 구분을 담당한다.

Back Worker는 Front Worker에서 전달된 작업을 받아 압축/복원/출력 버퍼 생성/전송 처리를 담당한다.

## 5. 대표 실험 결과

- 평균 지연시간: 약 135.558 ms
- 평균 처리량: 약 333.742 MB/s = 약 2.734 Gbps
- 평균 요청 처리량: 약 32.586 requests/s
- TCP 재전송: 0회

## 6. 주요 디버깅 항목

- FreeBSD와 F-Stack 코드 버전 차이
- HA/TCP 코드 전체 덮어쓰기 실패
- F-Stack 빌드 오류
- Linux socket path가 남아 있던 문제
- MS 비동기 WAN connect 실패
- WAN_CONNECTING 상태에서 TX queue가 막히던 문제
- EPOLLOUT 이벤트 처리 순서 문제
- ES listener가 F-Stack epoll에 등록되지 않던 문제
- worker CPU 역할 분리 문제
- perf 및 FlameGraph 생성 과정 정리
